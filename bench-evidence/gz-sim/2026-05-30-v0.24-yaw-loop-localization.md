# v0.24 — yaw-spin root cause localized (it's the inner loop, → v0.25)

Date: 2026-05-30. gz Harmonic, geo-hover scenario, `--home=…488`.

v0.24 was scoped as "control allocation" to fix the v0.23 maneuver-induced
yaw spin. A systematic investigation **falsified that scope**: the
actuation/allocation is fine; the residual is an **actuator-dynamics
instability in the yaw control loop** — squarely v0.25 (robust inner loop).

## The elimination (each a gz experiment)

| Hypothesis | Test | Result |
|---|---|---|
| Thrust-floor throttles yaw authority | floor 0.5 vs 0.2 | spins the same → **NOT the floor** |
| Actuator yaw disturbance (SDF/drag) | open-loop equal motors | true yaw exactly 0 → **no disturbance** |
| Yaw control chasing a lagged estimate | **YAW_OFF** (zero yaw torque) | compass holds **exactly 90.0° / 15 s** → spin is **control-induced** |
| Estimate lag (compass latency) | Pose_V rate | **~93 Hz**, not lagged |
| Estimate lag (weak fusion) | tight compass (YAWVAR 0.0002) | IEKF yaw tracks within **1°** — **yet still spins** |
| Wrong yaw-torque sign | analytic check | sign is **correct** (body below setpoint → +yaw torque → rotates up) |

## Conclusion

With yaw control OFF the body holds heading perfectly and **full
position-hold nearly closes (final 1.22 m, rms 1.04 m)**. With yaw
control ON it spins **even with a 1°-accurate estimate and correct
sign**. That leaves one cause: **actuator dynamics**. Quad yaw authority
comes only from rotor-drag differential, which needs large motor-*speed*
changes — and gz motors have real spin-up time constants. The geometric
controller commands yaw torque assuming *instant* actuation; the motor-
speed lag makes the yaw loop a delayed loop → oscillation → spin.
Roll/pitch need only tiny fast thrust changes (high authority, negligible
delay) → stable.

This is exactly the unmodeled-actuator-dynamics problem **INDI/ADRC
(v0.25)** solve. Per docs/research/v0.25-inner-loop-sota.md the choice is
**ADRC (geometric extended-state-observer)** — algebraic-Lyapunov-
provable, SE(3)-native, estimates+cancels the lumped disturbance.

## What this means for the roadmap

- **v0.24 (allocation)** is NOT the yaw fix (actuation is fine). It
  remains valuable for hex/octo + rotor-loss (v0.26): the PX4 sequential-
  desaturation allocator with a swappable, drag-aware effectiveness
  matrix (docs/research/v0.24-control-allocation-sota.md). Re-scope v0.24
  to that forward-looking allocator; it is not on the position-hold
  critical path.
- **v0.25 (ADRC inner loop)** IS the yaw fix and the path to closing
  active-yaw position-hold.

## Validated this far (unit-tested + gz)

- IEKF (relay-iekf, 9 tests): full state, all updates, per-axis q_gyro.
- Geometric SE(3) (relay-geo, 5 tests): no tilt-yaw coupling, Ψ→0.
- gz: tilt control perfect (no Euler tip-over); YAW_OFF full
  position-hold **1.22 m / 1.04 m**. The verified estimator + outer-loop
  controller work; the gap is the inner-loop yaw dynamics (v0.25).
